# 13. 개발 로드맵 · 품질 기준 · 소넷용 작업 프롬프트

> 이 문서는 구현 에이전트(소넷)가 **출시 품질**로 만들 수 있게, 순서 · 완료 기준 · 검수 방법을 못 박아 둔 것이다.

## 0. 마스터 프롬프트 (Claude Code에 처음 한 번 붙여 넣기)

```text
너는 2D 픽셀아트 게임을 출시해 본 시니어 게임 개발자이자 픽셀 아티스트이고, '손맛(game feel)'을 집요하게 다듬는 사람이다.
이 저장소의 docs/ 폴더가 「점선정원: 씨앗 수비대」의 기획서이고, 이 기획서가 유일한 기준이다.

작업 규칙:
1. 먼저 docs/README.md와 docs/01-vision.md, docs/13-roadmap-qa.md를 끝까지 읽어라. 그다음 지금 마일스톤에 필요한 문서만 읽어라.
2. 마일스톤은 M0부터 순서대로 하나씩만 진행한다. 다음 마일스톤으로 먼저 넘어가지 않는다.
3. 마일스톤마다 끝내기 전에 반드시: (a) npm run lint, npm test 통과 (b) 게임을 실제로 실행하고 Playwright로 주요 화면 스크린샷을 찍어 직접 본다
   (c) 13-roadmap-qa.md의 완료 기준(DoD)과 체크리스트를 표로 하나씩 대조한다 (d) 부족한 점을 고친 뒤 다시 확인한다 (e) 커밋한다.
4. 기획서와 다르게 해야 하거나 기획서가 모호하면, 네 가지 디자인 필러(키우는 맛 · 지키는 맛 · 찾는 맛 · 보는 맛)에 가장 맞는 쪽을 고르고
   docs/DECISIONS.md에 날짜 · 내용 · 이유를 한 줄로 기록한다. 범위를 몰래 줄이지 않는다.
5. 아트는 기획서의 절차적 픽셀아트 규칙(02 문서)대로 만들고, 그 결과물이 곧 최종 아트다. 회색 사각형 같은 임시 그림을 남긴 채 마일스톤을 끝내지 않는다.
6. 얼굴은 눈(점)과 입(선)만, FaceRenderer로 런타임에 그린다. 02 문서 5-2절의 과장 비율 검수기를 통과해야 한다.
7. 화면에 보이는 모든 상태 변화에는 애니메이션이나 소리 같은 반응이 따라야 한다. 반응 없이 숫자만 바뀌는 곳이 없게 한다.
8. 모든 글자는 i18n 파일에서 가져오고, 모든 밸런스 수치는 data/ 파일에 둔다. 수치를 바꾸면 DECISIONS.md에 적는다.
9. 한 파일이 500줄을 넘으면 나눈다. 전투 로직에서는 Math.random을 쓰지 말고 시드 RNG를 쓴다. setTimeout 대신 씬 시간(트윈 · 타이머)을 써서 일시정지와 배속에 맞춘다.
10. 마일스톤을 끝낼 때마다 "한 일 / 스크린샷 경로 / DoD 대조표 / 남은 문제 / 다음 할 일"을 짧게 보고한다.

지금은 M0부터 시작해라.
```

## 2. 완료 기준 (DoD)

### M0
- [ ] `npm run dev`로 실행하면 타이틀 글자(Galmuri)가 어떤 창 크기에서도 번짐 없이 정수 배율로 보인다.
- [ ] 창 크기를 바꿔도 안전 영역 640×360이 유지되고 남는 영역은 배경색으로 채워진다.
- [ ] 저장 → 불러오기 왕복, 체크섬 손상 → 백업 복구, 조사 처리 단위 테스트가 통과한다.
- [ ] `?debug=1`로 디버그 오버레이(FPS)가 뜬다.

### M1
- [ ] 아트 갤러리에 100종 × 6단계가 오류 없이 나온다(지연 생성 포함).
- [ ] 얼굴 검수기 위반 0, 팔레트 밖 색 0(자동 테스트).
- [ ] 실루엣 모드 스크린샷에서 같은 계열끼리는 닮고, 다른 종끼리는 구분된다(직접 보고 판단, 애매한 종은 부품을 바꿈).
- [ ] 표정 16종이 모든 얼굴 유형에서 자연스럽다. 시선 추적과 엇갈린 깜빡임이 동작한다.
- [ ] UI 키트 데모 화면: 패널 3종, 버튼 4상태, 게이지, 툴팁, 숫자 폰트.

### M2
- [ ] 씨앗에서 개화까지 돌봄 18종을 모두 써서 키울 수 있다(디버그 시간 가속 허용).
- [ ] 모든 돌봄 행동이 0.1초 안에 표정 · 몸짓 · 소리(임시 ZzFX라도)로 반응한다.
- [ ] 처음 눈뜨기 → 이름 짓기 연출이 들어갔다.
- [ ] 오프라인 12시간 시뮬레이션 테스트가 통과한다(욕구 하한 20, 묶음 계산, 시계 되돌림 처리).
- [ ] 30분 동안 직접 놀아 보고 "귀찮은 순간"을 DECISIONS.md에 적고 고쳤다.

### M3
- [ ] 챕터 1의 6개 스테이지(보스 B1 포함)를 산책 · 보통으로 끝까지 할 수 있다.
- [ ] 같은 입력이면 같은 결과가 나온다(시뮬레이션 결정성 테스트).
- [ ] 시뮬레이터로 1-1~1-6 보통 클리어율이 목표 범위(70–80% ±10%p) 안이다.
- [ ] 적 300 + 투사체 600 부하 테스트에서 데스크톱 60fps를 유지한다.
- [ ] 결과 화면이 06 문서 13절의 순서를 따른다(별 → MVP → 경험치 → 보상 순차 공개).

### M4
- [ ] 데이터 검증 테스트 통과(100종 · 적 34 · 보스 7 · 스테이지 42 · 레시피 33 · 의식 4).
- [ ] 모든 식물을 전투에 냈을 때 능력이 **눈에 보이게** 작동한다(갤러리처럼 '능력 시연' 디버그 씬으로 하나씩 확인).
- [ ] 모든 스테이지가 보통 난이도에서 봇으로 클리어 가능하다.
- [ ] 레시피 33개를 모두 실제로 만들 수 있다(테스트로 확인).

### M5
- [ ] 새 저장으로 시작해 튜토리얼 목표 시각(10 문서 4절)을 ±30% 안에서 지킨다.

### M6
- [ ] 「손맛 20」 체크리스트(아래 3절) 전부 '예'.

## 4. 재미 점검 질문 (마일스톤마다 직접 플레이하고 답한다)
1. 처음 3분 안에 식물이 눈을 뜨고 이름을 지어 줬는가? 그 순간 기분이 좋았는가?
2. 같은 돌봄을 계속 반복해서 지루했던 순간이 있었는가? 있었다면 자동화 · 빠른 돌봄 시점을 앞당긴다.
3. 전투에서 "이 식물 데려오길 잘했다"는 순간이 한 판에 한 번 이상 있었는가?
4. 질 때 "왜 졌는지" 바로 알 수 있었는가? 패배 팁이 맞는 말이었는가?
5. 봉투를 열 때 등급이 높을수록 실제로 더 설레었는가?
6. 낮은 등급 식물도 계속 쓸 이유가 있었는가(초반 효율 · 시너지 · 교배 재료 · 색변이)?
7. 메인화면에서 할 게 없어서 멍하니 있었던 순간이 있었는가?

## 7. 자주 하는 실수 (금지 목록)
- 회색 사각형 · 임시 그림을 남긴 채 다음 단계로 넘어가기
- 얼굴을 몸 스프라이트에 직접 그려 넣기(표정이 안 바뀜)
- 정수가 아닌 배율로 확대하기(픽셀이 뭉개짐), 일부 스프라이트만 따로 확대하기(믹셀)
- 코드에 한글 문자열을 직접 쓰기, 조사를 '이(가)'처럼 얼버무리기
- 밸런스 수치를 말없이 바꾸기
- 시스템을 거치지 않고 씬에서 상태를 직접 바꾸기
- 오프라인 계산을 초 단위로 돌려 멈춤 만들기
- 전투에서 `Math.random`, `setTimeout` 쓰기
- 500줄이 넘는 거대한 파일
- "나중에 다듬기"로 미루고 손맛을 빼먹기
